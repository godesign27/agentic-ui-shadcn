BRAND SETUP MODE

This prompt is for generating brand color token scales from base brand color inputs in a shadcn/ui implementation.

Your task is to generate deterministic color scales (50-900) and write them as CSS variables in the shadcn/ui theme system.
Do NOT generate UI components or modify component files.

────────────────────────────────
INPUT

Accept base brand color(s) as input:
- Primary brand color (required)
- Secondary brand color (optional: brand-2)
- Tertiary brand color (optional: brand-3)
- Quaternary brand color (optional: brand-4)

Input format: Hex color codes (e.g., #3b82f6)

────────────────────────────────
DETERMINISTIC COLOR SCALE GENERATION

Generate full color scales (50, 100, 200, 300, 400, 500, 600, 700, 800, 900) for each provided brand color using these deterministic rules:

**REQUIRED: 50-900 Scale Generation**
- Each provided base color MUST generate all 10 tonal steps: 50, 100, 200, 300, 400, 500, 600, 700, 800, 900
- Steps MUST be written as CSS variables (tokens), not hard-coded into components
- Token naming MUST follow shadcn/ui CSS variable conventions
- All tokens must be accessible via CSS custom properties in HSL format (e.g., --brand-50: 210 40% 98%)

For each base color:
1. **500 = base color** (the provided input color)
2. **Lighter shades (50-400)**: Systematically lighten by increasing lightness
   - 50: Lightest (95-98% lightness)
   - 100: Very light (90-93% lightness)
   - 200: Light (80-85% lightness)
   - 300: Medium-light (70-75% lightness)
   - 400: Slightly light (60-65% lightness)
3. **Darker shades (600-900)**: Systematically darken by decreasing lightness
   - 600: Slightly dark (45-50% lightness)
   - 700: Medium-dark (35-40% lightness)
   - 800: Dark (25-30% lightness)
   - 900: Darkest (15-20% lightness)

**Algorithm (HSL-based)**:
- Convert base color to HSL
- For lighter shades: Increase L (lightness) while maintaining H (hue) and S (saturation) proportionally
- For darker shades: Decrease L (lightness) while maintaining H (hue) and S (saturation) proportionally
- Output in HSL format without hsl() wrapper (e.g., "210 40% 98%") for shadcn/ui CSS variables

**Saturation adjustment**:
- Lighter shades (50-400): Gradually reduce saturation by 5-10% per step to avoid washed-out colors
- Darker shades (600-900): Gradually increase saturation by 5-10% per step to maintain color richness

────────────────────────────────
SHADCN/UI TOKEN OUTPUT FORMAT

Write colors as CSS variables in HSL format (without hsl() wrapper) following shadcn/ui conventions.

**Output location**: src/index.css (in the :root and .dark selectors)

For primary brand color:
- Add to :root: --brand-50 through --brand-900 (10 variables)
- Add to :root: --brand (alias for brand-500)
- Add to :root: --brand-foreground (calculated for sufficient contrast on brand-500)
- Add to .dark: Same variables with adjusted values for dark mode

For secondary brand color (if provided):
- Add to :root: --brand-2-50 through --brand-2-900 (10 variables)
- Add to :root: --brand-2 (alias for brand-2-500)
- Add to :root: --brand-2-foreground (calculated for sufficient contrast on brand-2-500)
- Add to .dark: Same variables with adjusted values for dark mode

For tertiary/quaternary colors, follow same pattern.

**shadcn/ui CSS Variable Format**:
```css
:root {
  --brand-50: 210 40% 98%;
  --brand-100: 210 40% 96%;
  /* ... */
  --brand-500: 210 40% 50%;
  /* ... */
  --brand-900: 210 40% 15%;
  --brand: var(--brand-500);
  --brand-foreground: 0 0% 100%; /* or 0 0% 0% based on contrast */
}
```

**Tailwind Integration**:
- Update tailwind.config.js to extend theme.colors with brand colors
- Map brand tokens to Tailwind color utilities (e.g., bg-brand, text-brand-foreground)
- Example:
```js
colors: {
  brand: {
    50: 'hsl(var(--brand-50))',
    100: 'hsl(var(--brand-100))',
    // ... etc
    DEFAULT: 'hsl(var(--brand))',
    foreground: 'hsl(var(--brand-foreground))',
  }
}
```

────────────────────────────────
CONTRAST CALCULATION FOR FOREGROUND COLORS

Calculate brand-foreground colors using WCAG AA contrast requirements:
- For brand-500: Calculate whether white (0 0% 100%) or black (0 0% 0%) provides better contrast
- Use the color that meets WCAG AA (4.5:1 contrast ratio minimum)
- If neither meets AA, adjust lightness to find the closest color that does

Apply same logic for brand-2-foreground, brand-3-foreground, brand-4-foreground.
